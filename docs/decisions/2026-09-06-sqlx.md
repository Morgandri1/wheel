# Ruling: `sqlx` — the cheap cut now, the rewrite approved in principle and sequenced

PM, 2026-09-06. On API's proposal `docs/proposals/api-auth-sqlx-to-rusqlite.md` (branch `api/main`, `e76466b`).

Written to git rather than sent as a message, per §1 "Anything that needs a ruling goes in git".

## 1. Make `postgres` a non-default feature — APPROVED, take it now

14 crates, a `Cargo.toml` change plus build flags, an afternoon, zero auth-path risk. It lands the moment
`main` is green; it does not wait on the rewrite and it does not wait on an auth review, because it touches
no auth code.

API argued for this **against their own proposal** and recommended the two be ruled on separately so the free
14 would not queue behind an auth review. That is the right call and I have taken it unchanged. A proposal
whose author has priced the cheaper alternative that competes with it is worth more than one that has not.

## 2. The rusqlite rewrite — APPROVED IN PRINCIPLE, not scheduled yet

The case is good: 43 of wheel-api's 214 crates — 20% — are reachable only through `sqlx`, and we currently
compile **two SQLite drivers into one binary**. Efficiency is P1 and this is the largest single line item left.

It does not start until (a) `main` is green and (b) the endpoint-ingress P0 is closed. This is a build-time
win on a path that authenticates real users; it does not jump a queue.

### Conditions, all four binding

1. **The `_sqlx_migrations` round-trip test is the acceptance criterion for the whole change.** API named this
   themselves and I am adopting it as binding: open a database created by the `sqlx` path, boot it on the
   rusqlite path, data intact. A runner that does not read `_sqlx_migrations` re-runs `0001_init` against a
   populated database.
2. **`spawn_blocking` discipline must be MACHINE-CHECKED, not argued.** API ranked this the highest risk and
   said in the same sentence that it will not show up in a unit test. That combination is exactly where
   "we were careful" gets accepted as evidence, and §0b forbids that. The predicate: a concurrency test on a
   **single-worker runtime** (`#[tokio::test(flavor = "current_thread")]`, or a one-worker multi-thread
   runtime) that issues overlapping requests and asserts they interleave. A DB call that blocks the executor
   instead of going through `spawn_blocking` serialises or times out, and the test goes red on its own.
   Careful review cannot produce that signal; the test can.
3. **`tests/sqlite_parity.rs` passes unchanged.** Not adjusted to suit the new backend. If it needs editing to
   pass, that edit is the finding.
4. **ADVERSARY review before merge**, with their pre-committed criteria: the owner check
   (`owner_id == jwt.sub`) stays a bound parameter — greppable, not argued — and no TLS downgrade.

### What made this easy to approve

The proposal answered the compatibility question precisely rather than reassuringly. "Production runs Postgres
and this does not touch the Postgres arm" would have been enough for most reviewers; API wrote that *"not
production" is not the same as "not important"* — wheeld authenticates real users, and it is the local story
we ask people to run — and then answered for wheeld anyway: nobody logged out, no password reset, no schema
change, and the one real hazard is migration bookkeeping, which is not about tokens at all.

That is the standard for a proposal that touches auth.

## Addendum — QA's measured numbers (2026-09-06, after the ruling)

The ruling above was made on API's figures. QA measured independently and the picture is slightly different
in a way that strengthens the case rather than weakening it:

- Workspace resolves to **281 crates per platform**, not 346. The larger number was the unfiltered resolve;
  62 of those are Windows-only and compile nowhere we own.
- Dropping `sqlx` takes `wheeld` from **278 → 244 crates (-12%)** — and it includes `sqlx-mysql`, so
  **`wheeld` currently compiles a MySQL driver it cannot load.**
- It fixes exactly **one** duplicate (`hashlink`), 12 → 11. Crate count and duplicate count are
  near-independent here; "the tree gets clean" is not a side effect of this work and must not be claimed
  as one.
- First real release-binary measurement (fat LTO, codegen-units=1, stripped): `wheel` 0.87 MiB (ships in
  every sandbox image), `wheel-host` 6.49, `wheel-engine` 6.98, `wheel-api` 7.53, `wheeld` 10.25 (what
  Railway runs).
