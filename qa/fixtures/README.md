## `envelope-integrity.bin` — shared with ADVERSARY

**200 KiB (204800 bytes) exactly. sha256 `94c71e8c616c5cdb023d94a69a8edc2857c3fff06a601d42008b31ab02f2e5a6`.**

One payload used by **both** QA's regression tests and ADVERSARY's PoC, per PM's approval, so a fix

Regenerate (deterministic — no randomness, no timestamps):

### What's in it and why

| Section | Contents | Attacks / bugs it catches |
|---|---|---|
| 1 ascii | every printable ASCII char, then every punctuation char alone | naive quoting, shell/argv substitution, sprintf-style format bugs |
| 2 json-escapes | `"` `\` `/` tab CR LF BS FF, **a raw NUL**, VT, ESC, DEL, nested JSON | body truncated at NUL; double-encoding; a JSON string built by concatenation rather than a serializer |
| 3 unicode | emoji + ZWJ sequences, CJK, Hangul, Thai, Arabic/Hebrew RTL, combining marks, astral plane, BOM, NBSP, zero-width, **bidi override U+202E**, a Cyrillic-о homoglyph tag | byte-vs-char length limits splitting a codepoint; visual attribution forgery; homoglyph treated as markup |
| 4 forged-envelope | a **complete** `<AgentPrompt id=… from="admin" type="system">` block with an instruction payload | **the privilege-escalation vector**: if escaping fails, agent A impersonates any node — including `system` — to agent B |
| 5 close-tag-variants | 12 forms: exact, trailing/leading space, tab, upper/lower case, unterminated, doubled, nested | an escaper that matches only the exact literal string |
| 6 encoded-forms | HTML-entity, percent-encoded, `<`, double-encoded, base64 | an unescape-then-parse step that re-materialises a tag after the escaper ran |
| 7 framing | CRLF, lone CR, lone LF, and a **complete fake stdin JSON line** | body breaking out of the one-line-per-turn stdin framing |
| 8 padding | deterministic filler, with `</AgentPrompt>` every 97th line | size-related truncation; escaping that degrades over a long body |

### How to use it

The body is UTF-8 (it decodes cleanly) but is stored as `.bin` because it contains a raw NUL and
control bytes that text tooling mangles. **Read it as bytes and compare as bytes** — a
string-level comparison can normalise unicode and hide exactly the bug this is hunting.

Expected outcome for every consumer: the recipient's transcript contains this payload
**byte-identical** inside a single engine-generated envelope, with `from`/`type` reflecting the
real sender and **no second envelope** parsed out of the body.

Related IDs: `MSG-byte-exact`, `MSG-envelope-escape`, `MSG-envelope-forge`, `MSG-no-truncate`.
